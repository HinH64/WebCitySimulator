# WebCitySimulator 企劃（v5）

> 一句話：**網頁版的《模擬城市》／《Cities: Skylines》，但從一座真實存在的城市開始**（現在是 1997 年 7 月的香港），而不是虛構的地方
> 主要操作：分配部門撥款 → 觀察城市發展
> 真實歷史：大事照樣發生，作為背景；結局揭曉真實的香港走了哪條路，是好玩的部分，**不是遊戲目標**
> 靈感來源：《80億分之1》（1 in 8 Billion，1in8b.life）
> 工作名稱：《平行香港》
> 核心模型：見 [MODEL.md](MODEL.md)
> 目前進度：4g 平衡已完成；3e.1 試看後選定 2.5D，3e.2 已接入遊戲（[CITY-MAP.md](CITY-MAP.md)），下一步補 3e.3 裝置及效能驗證。更多建築素材、鐵路細節及整體版面美術押後，完整 3D 暫緩。3f「建出不同的香港」規劃見 [SPATIAL.md](SPATIAL.md)，3f.1 發展方向及建成年代、3f.2 地標已完成，下一步 3f.3 地點及密度有後果，讓不同決定建出格局、外觀和地標都不同的香港；4h 分享卡建議放在 3f 之後。

## 2. 定位

**遊戲是城市經營，不是歷史問答。** 玩家的目標是把自己的城市經營好；遊戲途中只看城市本身（指標、財政、人口），不講跟真實歷史差多少。結局不打分，因為這是「如果當年……」的遊戲，不是為政策評分。

真實歷史的角色：
1. **起點和背景**：城市由真實的 1997 年香港開始，金融風暴、SARS、疫情等大事照樣發生
2. **抉擇的題材**：政策分兩層。**一般政策**像 SimCity 的法令或 Cities: Skylines 的政策，名稱通用、一開局就可以用，只會在玩家改變時改變；**歷史抉擇**是有名有姓的歷史關口（八萬五、辣招、2 元乘車），會設定一般政策，不回覆就維持現狀
3. **結局的揭曉**：你的香港跟真實香港的總結、走勢和數字對比、每個關口歷史上怎樣選，在結局一次過揭曉，是額外的樂趣
4. **模型的驗證**：照真實政府的做法玩一局，結果要等於真實數字（自動測試會檢查）

為甚麼結束在現在（2026）：過去有數據，未來只有推算；「如果當年……」也比預測未來更有共鳴。未來模式放到第 5 階段。

## 3. 玩法（摘要，詳見 MODEL.md）

| 層次 | 內容 |
|---|---|
| 主要操作 | **預算面板**：六個部門的撥款水平（50%–200%）。低於 100% 服務變差，高於 100% 擴建，但有工程延遲 |
| 次要操作 | 稅率（薪俸稅、利得稅、差餉、銷售稅）、債務、一般政策（19 項，分五類）、待決定的歷史抉擇 |
| 主要數值 | **庫房**（億元）、**人口**（萬人），每月更新 |
| 觀察 | **城市新聞**（畫面主角）：大事、一般城市新聞、城市動態、統計數字、里程碑、年度報告；市民最關心；六項發展指標；需求、人口面板 |
| 系統自動計算 | 保養開支、工程延遲、收入、吸引力帶動移民、經濟五行業和歷史衝擊 |
| 自動暫停（⚙） | 定期暫停（不暫停／每 1、3、5 年）、抉擇時暫停、危機時暫停、打開面板時暫停 |
| 結局 | 城市稱號和跟真實香港比較的總結（不評分）；走勢、數字、歷史抉擇、政策和撥款對比 |

版面：桌面版以城市新聞為主欄，指標縮成頂部一行，面板放在可收起的右欄；手機版新聞佔滿畫面，面板由底部分頁打開。

內容方針：
- 聚焦城市規劃與民生，不模擬選舉或政治事件；有政治事件的年份只呈現經濟數字。
- 每項數據標註來源與年份。
- 模型是簡化的遊戲模型，會明說，不假裝是預測。

## 4. 原型（第 0 階段，已完成）

驗證了「真實歷史 + 分配 + 抉擇 + 結局對比」這個概念：
- 20 點分配到六項指標，每 5 年重新分配
- 模型只計算玩家跟歷史的差距
- 17 個歷史抉擇（選完即時揭曉）、38 個歷史事件、14 個平行時空事件
- 結局有走勢圖、真實單位對照、過往任期

試玩後決定改變的地方：
- 分配和指標一對一、指標太抽象 → 改為部門撥款，加入實體建設和需求與供應
- 欠缺具體的錢和人口 → 加入庫房和人口
- 每次抉擇揭曉歷史太打擾 → 改到結局揭曉
- 強制暫停打斷觀看 → 改為玩家自己設定

## 5. 技術

- Vite + TypeScript + React，純靜態網站
- 模擬引擎是純 TypeScript，不依賴介面，每月計算一次
- 事件、政策、數據、參數寫成資料檔
- Vitest：決定性、會計恆等（每月庫房變化 = 收入 − 開支）、歷史基準校準（誤差範圍）、平衡測試
- 部署：Vercel（Git 整合，每個分支有預覽網址）；GitHub Actions 只跑測試和建置
- 暫時不需要資料庫：數據跟網頁一起打包，玩家紀錄存在瀏覽器

## 6. 開發階段

每個階段完成時都可以在 Vercel 試玩。

| 階段 | 內容 | 完成標準 |
|---|---|---|
| **0. 原型**（已完成） | 見第 4 節 | 驗證概念可行 |
| **1. 核心玩法**（已完成） | [MODEL.md](MODEL.md) 的全部內容：部門撥款、庫房、人口、稅率、債務、政策、需求與供應、吸引力與移民、經濟五行業、收件匣、自動暫停設定、新結局 | 歷史基準玩法通過誤差測試；平衡測試通過；可以玩完一整局 |
| **1.1 定位調整**（已完成） | 絕對評分（真實香港同標準評分作揭曉）；政策分為一般政策（通用名稱、開局可用、只由玩家改變）和歷史抉擇；約 50 個一般城市新聞和里程碑；以城市新聞為主的版面 | 照歷史玩（關掉隨機新聞）仍然等於真實；評分和平衡測試通過 |
| **2. 真實數據與公開測試** | 用官方數據取代約數、完善數據來源頁、按試玩意見調整平衡、在 Vercel 正式上線 | 每個數字都有官方來源；公開網址可玩 |
| **3. 像素地圖**（已完成） | 按城市的發展**自動建造**香港地圖：新市鎮、鐵路、填海、工業區、郊野公園。玩家不用自己放建築；每局的發展不同，地圖也不同（例如重工業和重環保的香港看起來不一樣）。加入圖層，例如人口密度、樓價、鐵路覆蓋。計劃見 [MAP.md](MAP.md) | 地圖隨發展自動變化，不同玩法看得出分別 |
| **4. 內容擴充** | 更多事件；時間控制；看得見的工程；暫緩的機制（舊樓老化、施政阻力與民望、追蹤市民）；加入事件後再調整一次平衡；分享卡；英文版（暫緩）。計劃見 [CONTENT.md](CONTENT.md) | 按需要逐項完成 |
| **5. 未來模式** | 由 2026 繼續玩下去，用官方人口和經濟推算 | 可以玩到例如 2056 年 |
| **6. 更多城市** | 其他城市，或像原作一樣「隨機抽一座世界城市」 | 至少一個新城市 |
| **7. 更早開局** | 1954、1973 開局，同樣以真實歷史作基準；先確認 1997 年前有沒有可以直接下載的數據（原本在第 4 階段，見 [CONTENT.md](CONTENT.md) 第 12 節） | 至少一個更早的開局可以玩完 |

**可選支線：玩家統計**（例如「42% 玩家選擇停建居屋」）需要資料庫。等第 2 階段上線、有玩家之後再決定。

**第 4 階段：民望與被迫下台**（4a，已完成，做法見 [MODEL.md](MODEL.md) 第 16 節）。加入民望之前，甚麼都不做也不會提早結束，只是結局較差（六項指標約有 5 項不及真實香港）：撥款一直維持 1997 年的水平（房屋 130%、交通 125%，即繼續擴建），各部門維持服務所需的錢也會跟人口和需求自動增加；1997 年的政策（例如繼續興建居屋）也不差。單看問題有多嚴重並不足夠，因為甚麼都不做的城市在 2026 年的住屋問題反而比真實香港輕。民望要看政府有沒有回應：
- 頂部顯示民望（0–100）。
- 某方面的問題持續嚴重，而玩家沒有增加該部門的撥款或改變相關政策，民望慢慢下跌；有回應就慢慢回升。
- 民望長期低於某個水平（例如超過一年），任期提早結束（「被迫下台」），跟「財政懸崖」一樣。
- 調校目標：照歷史玩一定做完任期；甚麼都不做約在 2000 年代中後期下台；有看需求、調撥款的玩法不會下台。
- 結果：照歷史玩做完任期（民望最低約 45）；甚麼都不做 2008–2009 年被迫下台；看需求面板的玩法做完任期。

加入更多事件之後，事件本身也會改變各種玩法的結果，所以第 2 階段只修正了明顯失衡的選擇（見 MODEL.md 第 15 節），整體平衡留待第 4 階段加入事件和民望後再調整。
