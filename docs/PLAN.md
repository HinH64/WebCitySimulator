# WebCitySimulator 企劃（草案 v2）

> 靈感來源：《80億分之1》（1 in 8 Billion，1in8b.life）
> 概念：選一座真實城市（先做香港），從真實的起始狀態開始，你透過「分配施政重心」和「應對事件」決定它往後幾十年的發展
> 狀態：待確認後開始實作

---

## 1. 《80億分之1》做了什麼

| 面向 | 內容 |
|---|---|
| 作者 / 上線 | 韓國獨立開發者 Jin Hwi-eus（Jin's Earth），2026-10-05 上線，自述用生成式 AI 約 4 小時做出第一版 |
| 核心概念 | 從全球 80 億人中隨機出生成一個人，國家、家庭、貧富都不能選 |
| 數據 | 聯合國、WHO、世界銀行等公開統計，涵蓋約 172 個國家與地區 |
| 開局設定 | 出生年代（過去 / 現在 / 未來）、抽國家的方式、人生長度（約 30 / 60 / 90 分鐘） |
| 數值 | 健康、幸福、知識、人際關係，各 0–100 |
| 操作 | 依年齡階段設定一個「生活重心」；時間自動流動，每年 1–3 行事件；關鍵時刻跳出選項；可暫停、加速、自動選擇 |
| 結局 | 死亡年齡與死因、人生回顧、S–D 評級、分享卡片、存在瀏覽器的「前世紀錄」 |
| 其他 | 免費、免註冊、無廣告、純網頁；多語系；建議 15 歲以上 |

### 城市版的對應

| 原作 | 城市版 |
|---|---|
| 一個「生活重心」（單選） | **六項指標的分配式重心**：把資源點分配到住屋、經濟、交通、環境、民生、財政 |
| 每年 1–3 行事件 | 城市新聞，例如「2031：古洞北首批公屋入伙」 |
| 關鍵時刻跳出選項 | 事件附帶 2–3 個選項，例如「環團反對填海：堅持 / 縮減 / 擱置」 |
| 4 項數值 0–100 | 6 項城市指標 0–100，背後由真實單位的數據支撐 |
| 人生長度 | 任期 30 年（2025–2055） |
| 死亡與死因 | 任期結束時的「城市稱號」，例如「宜居之城」「擠迫之城」；財政崩潰則提早卸任 |
| S–D 評級、分享卡、前世紀錄 | 成績表、評級、「你的香港 2055」分享卡、過往任期 |

## 2. 玩法

### 2.1 開局
- 城市：香港
- 起始年份：2025
- 任期：30 年
- 速度：短 / 標準 / 長（約 15 / 30 / 45 分鐘一局）
- 種子碼：可輸入或分享，重播同一個隨機世界
- 設定第一次的重心分配

### 2.2 分配式重心（核心操作）
- 每個施政階段有 **20 個資源點**（每點 = 5%），分配到六項指標
- **財政**的點數代表「存起來」：不花掉，轉入儲備，用來抵禦危機
- 每 **5 年**自動暫停一次，讓你重新分配；期間也可隨時暫停調整，新分配由下一年生效
- 可選「自動」：沿用目前分配，事件也自動選

範例：
```
住屋 ●●●●●●      30%
經濟 ●●●●        20%
交通 ●●●         15%
環境 ●●          10%
民生 ●●●         15%
財政 ●●          10%
```

### 2.3 指標怎樣變化
每年每項指標的變化：

```
變化 = 投入效果 − 自然壓力 + 其他指標的連動 + 事件影響
```

1. **投入效果**：分配比例 × 當年可用資源（由經濟和財政決定），且邊際遞減（同一項投越多，每點效果越低）
2. **工程延遲**：住屋和交通的投入大部分要等工程完成才見效（約 3–8 年），在城市新聞中以「動工」「完工」呈現；民生和環境有一部分即時見效
3. **自然壓力**：不投入就會下滑，例如人口增長令住屋和交通變差、人口老化令民生變差、開發令環境變差
4. **連動**：

| 投入 | 正面影響 | 負面影響 |
|---|---|---|
| 住屋 | 民生 | 環境（用地）、財政（建屋成本） |
| 經濟 | 財政（稅收）、民生（就業） | 住屋（需求與樓價）、環境 |
| 交通 | 經濟、民生；令新發展區的住屋效果更好 | 財政 |
| 環境 | 民生 | 住屋（可用土地減少） |
| 民生 | 經濟（留住人才） | 財政（經常開支） |
| 財政（儲蓄） | 抵禦危機事件 | 當年其他項目的資源減少 |

設計目標：沒有一個分配可以讓六項都滿分，你的分配就是你的施政取向。

### 2.4 指標背後的真實數據
每項指標由幾個真實單位的數值換算成 0–100，起始值取自 2025 年的香港數據，成績表也用這些真實單位：

| 指標 | 背後的數值 |
|---|---|
| 住屋 | 公屋輪候年期、樓價入息比、人均居住面積、劏房人口 |
| 經濟 | GDP 增長、失業率、人均 GDP |
| 交通 | 平均通勤時間、住在鐵路站附近的人口比例 |
| 環境 | 綠地與郊野公園比例、空氣質素、碳排放 |
| 民生 | 安老院舍輪候、公立醫院輪候、貧窮率 |
| 財政 | 財政儲備可應付幾個月開支、年度盈餘或赤字 |

### 2.5 事件
- **一般事件**（只是發生，沒有選項）：依歷史頻率或條件觸發，例如颱風、暴雨、經濟周期、工程完工
- **抉擇事件**（2–3 個選項）：例如
  - 樓價急升：加辣 / 撤辣 / 不干預
  - 環團反對填海：堅持 / 縮減規模 / 擱置
  - 疫症爆發：嚴格防疫 / 有限度措施 / 照常
  - 工程超支：追加撥款 / 削減規模 / 延期
- **里程碑項目**：持續投入某項到一定程度，就會觸發真實的香港項目，例如住屋 → 北部都會區各分區、交椅洲填海、東涌東；交通 → 北環線等規劃中的鐵路
- 觸發條件看年份、指標高低、目前分配與隨機數

### 2.6 結局
- 任期結束出成績表：用真實單位列出 2025 和 2055 的對比（人口、公屋輪候、樓價入息比、通勤時間、綠地比例、儲備）
- **城市稱號**：依六項指標的組合決定，例如「宜居之城」「金融孤島」「擠迫之城」「綠色都會」
- 評級 S–D
- 提早結束：財政儲備耗盡時任期提早結束
- 分享卡：稱號、評級、六項指標雷達圖
- 「過往任期」存在 localStorage，提供匯出 / 匯入

### 2.8 內容方針
- 聚焦城市規劃與民生，不模擬選舉或政治事件
- 每項數據標註來源與年份，在「數據來源」頁公開
- 模型是簡化的，會明說，不假裝是預測

## 4. 技術架構

- **前端**：Vite + TypeScript + React，純靜態網站
- **模擬引擎**：純 TypeScript 模組，不依賴介面；用有種子的亂數產生器，同一個 seed 加上同樣的操作必定得出同一個結果
- **內容資料**：事件、里程碑項目、城市稱號都寫成資料檔（JSON），新增內容不用改程式
- **儲存**：localStorage（設定、過往任期），讀寫都包 try/catch
- **多語系**：繁中優先，之後加英文
- **測試**：Vitest
  - 單元測試：指標換算、連動、工程延遲、事件觸發
  - **平衡測試**：用多種固定分配（平均分、全押住屋、全押經濟等）各自動跑 1,000 局，確認沒有單一必勝的分配，評級分布合理
  - **隨機事件校驗**：颱風等事件的平均頻率要符合歷史
- **部署**：GitHub Pages（GitHub Actions 自動建置）

### 目錄結構
```
src/
  engine/        # rng, indicators, allocation, pipeline（工程延遲）, events, endings, sim loop
  data/          # 香港起始值、參數、事件、里程碑項目、城市稱號（JSON）
  ui/            # 開局、分配面板、指標條、城市新聞、抉擇對話框、成績表、分享卡
  i18n/          # zh-Hant.json
tests/           # 單元、平衡、事件校驗
docs/            # 企劃、模型說明、數據來源
```
