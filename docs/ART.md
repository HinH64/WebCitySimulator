# 第 3e 步：美術與地圖視覺（規劃草案）

> 2026-10-23 開始規劃，接在 4g 平衡完成之後、4h 分享卡之前。
> 建議方向：**懷舊城市經營遊戲的地圖，加上清楚易讀的繁中文介面；先比較 2.5D 原型與改善過的俯視圖，再決定正式畫法。**
> 目前只建立計劃；美術風格及投影仍待原型驗證。

## 1. 要達到甚麼

1. 一眼認得香港的海岸、新市鎮、密集市區和鐵路；放大後有城市經營遊戲的感覺。
2. 看得出哪裏正在施工、哪裏剛落成，以及玩家多撥款帶來甚麼；新增發展的實際面積仍由現有模型決定。
3. 地圖、預算面板、城市新聞和結局有一致的視覺語言，新聞和撥款仍然容易閱讀及操作。
4. 桌面和手機都能順暢觀看、縮放、拖動及由新聞跳到地點。

3D 本身不會增加玩法之間的土地差異。4d 已有具名工程、工地、地點跳轉和「你的發展」；3e 要令這些資訊更易察覺，不能靠放大實際發展範圍來製造差別。

## 2. 現有資料與界線

| 可用資料 | 位置 | 美術可以怎樣用 |
|---|---|---|
| 255 × 192 格，每格 250 米，25 種土地用途 | `src/data/mapBase.ts` | 海岸和用地輪廓、地面及建築類型；一格是概括用地，不是一棟樓 |
| 當月城市地圖、鐵路、霧霾 | `CityMap`，`src/engine/map.ts` | 所有畫法共用同一份輸入 |
| 公營、私人住宅和鄉村的每格住戶／人口估算 | `unitsPerCell`、`peoplePerCell` | 住宅體量的粗略分級；目前同類住宅共用密度，沒有逐區、逐棟的細緻資料 |
| 工地、施工鐵路、額外發展格及路線 | `CityWorks`，`src/engine/projects.ts` | 工地紋理、虛線、輪廓、地點標記；不再另算一份工程 |
| 年度快照和結局比較 | `src/ui/MapCompare.tsx` | 相同年份、相同投影及配色比較兩個香港 |

- 樓宇高低是按用地類型和粗略密度畫的**體量示意**，不能標成真實層數或高度。
- 沒有地形高度資料，第一輪原型以平面土地為基底；郊野用色塊和樹群表達。
- 建築外觀的小變化由格子坐標和用途穩定產生；兩個香港相同的格子外觀相同，不能因玩家種子不同而產生假差異。顯示不能消耗模擬的隨機數。
- 撥款、土地用途、單位數、選址、鐵路和民望規則沿用 4g；美術只讀取資料。
- 結局只呈現年度快照可以重建的內容，不能從沒有保存的工程管道猜測歷年施工進度。

## 3. 暫定美術方向

### 地圖

主題是「微縮香港」：輪廓清楚的地面、有限色盤、簡化建築群、固定光線。全港視角先讀得清海岸和發展分佈；放大後才增加屋頂、窗面、樹和工地細節。

| 類型 | 視覺特徵 |
|---|---|
| 公營房屋 | 整齊重複的樓群，暖黃色系，與私人住宅同時靠形狀和顏色區分 |
| 私人住宅 | 較緊密的樓群，磚紅／粉紅色系，體量只作示意 |
| 鄉村 | 低矮、分散的小屋 |
| 商業 | 簡化辦公樓群，屋頂和色調與住宅不同 |
| 工業、物流及港口 | 低層廠房、平屋頂和貨倉，港口保留清楚岸線 |
| 科學園、政府及社區 | 中低層組團，以用途配色區分；不虛構每格是哪間醫院或學校 |
| 郊野、休憩、農地、水塘 | 以地面為主，放大才出樹群或田格；不遮住城市輪廓 |
| 建造中 | 裸地和施工紋理；足夠放大才畫吊臂等細節 |
| 機場 | 保持低平、跑道容易辨認；1997 年啟德和之後赤鱲角的位置沿用資料 |

延續現有土地用途的色彩關係，先減少過於相近的色塊。霧霾保持輕薄，文字、鐵路、工程輪廓及新聞地點標記位於清楚可見的一層。

### 介面

- 保留桌面「新聞主欄＋右側面板」、手機底部分頁，以及庫房、人口、民望和六項指標的位置關係。
- 地圖可有像素或微縮模型感；新聞、政策、撥款和數字使用清楚的繁中文字體，不將長文變成像素字。
- 以城市年鑑／市政工作枱作視覺參考：有層次的面板、克制的邊框、清楚的時間和狀態。避免大面積仿舊紋理干擾閱讀。
- 統一按鈕、選中狀態、工程標籤、新聞類別和提示；保留現有語意色及深淺色模式。
- 「你的發展」使用輪廓／標記，新落成使用短暫提示，新聞地點使用獨立定位符號；不能只靠不同顏色區分三種狀態。
- 動畫只用於狀態變化，不持續閃爍；尊重減少動態效果設定。

## 4. 畫法比較與選擇準則

| 方案 | 要驗證的好處 | 主要代價 | 在計劃中的位置 |
|---|---|---|---|
| 改善過的 2D 俯視圖 | 香港輪廓、鐵路和四個資料圖層易讀，改善工地及發展提示 | 樓群立體感較弱 | 基準方案；即使選立體畫法，仍可供資料閱讀及降級使用 |
| Canvas 2.5D 固定斜視角 | 簡化樓群帶來城市感，保留現有前端架構 | 要處理投影、遮擋、定位及較長的全港畫面 | **第一個立體原型，暫定優先** |
| 可旋轉 3D | 可否實際改善遮擋、閱讀及探索 | 相機、觸控、效能、額外載入和匯出較複雜 | 先用同一小片區塊做技術樣板；有明確優勢才擴大 |

判斷依次看：**資訊是否清楚 → 操作是否順手 → 香港是否容易辨認 → 城市感 → 效能及維護成本**。不以「技術較立體」作通過條件。

2.5D 使用固定相機，先不加旋轉手勢；分析人口、樓價或鐵路覆蓋時，優先使用俯視圖，避免高度和陰影干擾數值顏色。介面是否提供常設「俯視／立體」切換，待原型比較後決定。

## 5. 第一輪原型的固定場景

由現有引擎產生同一批資料，所有畫法使用完全相同的月份、城市及鏡頭範圍，不手工加屋或改用地來美化效果。

| 場景 | 看甚麼 |
|---|---|
| 1997 年 7 月，全港 | 海岸、啟德機場、赤鱲角工地和整體方向是否認得 |
| 2010 年底，九龍／啟德一帶 | 密集城市的樓群、車站、工地及文字會否互相遮擋 |
| 2010 年底，房屋和交通固定 160%、其餘照歷史 | 4d 的新增屋邨、施工線和提早通車是否容易察覺；可直接由工程新聞定位 |
| 2026 年任期結束，照歷史及單一房屋 180% | 同一角度比較差異，兩邊的共同格子外觀必須一致 |
| 加快重建，2003 年和 2015 年舊區 | 工地移動及住宅回補是否可見；不將拆卸畫成永久消失 |

標準資料先固定種子 1、關掉隨機城市新聞；另用種子 7 和正常事件設定走一遍互動。日期上限沿用引擎，不另設一份遊戲終點。

第一輪先做九龍、天水圍及一個施工區的局部樣板，再放到全港。每個候選方向保存相同場景的桌面和手機截圖；3D 技術樣板只需相同區塊、樓群、鐵路及標記，不先做完整遊戲介面。

## 6. 實作接合方式（擬定）

1. 將地圖的繪製、投影及畫面外格子裁剪從 `MapView.tsx` 的操作介面抽出。共用輸入包含 `CityMap`、圖層資料、工程覆蓋、鏡頭和主題；繪製部分不操作 `GameState`。
2. 俯視及斜視各自提供坐標轉換；格子、鐵路、車站、工地和定位標記使用同一組轉換。反向轉換用於定位及以游標為中心縮放。
3. 斜視畫法按深度排序，固定高度上限；遮擋不能讓鐵路及重要定位標記消失。小格只畫簡化體量，放大才增加細節。
4. 靜態地面和樓群可快取，拖動時只畫畫面內的格子；新資料仍按現有季度節奏更新。繪圖快取不可反向修改引擎提供的網格。
5. `MapCompare.tsx` 兩邊使用相同投影、尺寸、光線及鏡頭；拖動分隔線只重新合成已畫好的圖。年度快照的月份對應沿用現有 `cityMapFrom` 呼叫。
6. 共用畫法必須可畫到離屏 Canvas，讓之後 4h 能產生同風格的縮圖。3D 樣板也要先驗證圖片匯出，不能只在互動視窗可用。
7. 視角偏好若需要保存，擴充現有地圖偏好並容許舊設定缺少新欄位；不改過往任期的儲存格式。

## 8. 驗收與量度

以下是原型的目標預算，實作後記錄實測結果；目前沒有宣稱已達標。

- **視覺**：全港能認方向；4 倍放大可區分公營／私人住宅、商業、工業和工地；新聞定位、施工虛線和「你的發展」清楚。
- **互動**：＋／−、全港、雙擊、Ctrl／Cmd＋滾輪、拖動和兩指縮放均可用；普通滾動仍然可以捲頁。手機不要求三指或右鍵操作。
- **畫面**：至少檢查 1440 × 900 桌面及 390 × 844 手機、裝置像素比 1／2、深淺色；文字不溢出，地圖不擋待決定抉擇及撥款工具。
- **效能**：記錄裝置、瀏覽器、視窗大小及視角。平移／縮放以桌面 60 fps、手機至少 30 fps 為目標，繪圖時間 P95 分別不高於 16.7／33.3 毫秒；全港和最大縮放均要量度。達不到時先降低細節、裁剪或使用俯視圖。
- **載入**：以 4g 的主程式約 170.5 KB gzip 為起點，先量度 2.5D 的增加；3D 若採用，獨立延遲載入並列出額外大小。第一輪不為沒有量度過的效果增加大型依賴。
- **一致性**：相同輸入的畫面結構一致，開關視角不改變城市快照、新聞抽取和任何引擎數值；照歷史時兩邊相同，純裝飾不產生假差異。
- **檢查方法**：投影及反投影、裁剪、標記對齊和網格不被修改可作單元測試；外觀、遮擋、手勢及可讀性用固定場景截圖和實際操作檢查。純配色修改不另寫鏡像測試。
- **回歸**：沿用全部引擎／地圖／工程／市民測試及 `npm run test:balance`，歷史恆等和 4g 目標不變；`npm run build` 通過。

## 9. 原型要解答的問題

1. 固定斜視角在手機是否比俯視更容易看清新增屋邨，還是遮擋更多？
2. 全港看得清、局部又有樓群細節，能否用同一畫法做到？
3. 四個資料圖層是否應固定回到俯視，並在返回土地用途時恢復原鏡頭？
4. 可旋轉 3D 在相同資料下增加了甚麼實際價值，是否值得載入及操作成本？
5. 需要常設視角切換，還是只保留一個正式畫法和自動降級？

原型結論要列出選擇的畫法、實測數字和捨棄方案的具體原因，再進入完整美術整合。4h 分享卡在畫法與配色定下後接續。
